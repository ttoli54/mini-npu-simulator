# Mini NPU Simulator

3×3부터 25×25까지 숫자 패턴과 필터를 직접 곱하고 더해 보는 Python 콘솔 프로그램입니다. 이 과정은 AI에서 사용하는 MAC(Multiply-Accumulate) 연산의 작은 모형입니다.

## 실행 환경과 실행 방법

- Python 3.8 이상
- 외부 라이브러리 없음
- 제공된 `data.json`은 원본 값을 수정하지 않고 프로젝트 루트에 둡니다.

```powershell
cd "C:\Users\수훈\OneDrive\문서\ChatGPT\코디세이 2\mini-npu-simulator"
python main.py
```

모드 2는 기본적으로 `main.py`와 같은 폴더의 `data.json`을 읽습니다. 다른 파일을 분석하려면 다음처럼 경로를 인자로 줄 수 있습니다.

```powershell
python main.py C:\path\to\data.json
```

테스트:

```powershell
python -m unittest -v
```

## 구현 요약

- `npu.py`의 `mac_2d()`가 이중 반복문으로 같은 위치의 값을 곱해 누적합니다.
- `mac_1d()`는 같은 데이터를 길이 N²의 1차원 배열로 펴서 같은 MAC을 수행합니다.
- `EPSILON = 1e-9`이며 `abs(A-B) < EPSILON`이면 `UNDECIDED`로 처리합니다.
- 모드 1은 A/B 필터와 패턴을 각각 3줄씩 입력받고, 점수·10회 평균 시간·최종 판정을 한 결과 구역에 출력합니다.
- 모드 2는 `size_N_번호`에서 N을 추출해 `filters.size_N`을 선택합니다.
- `+`와 `cross`는 `Cross`, `x`는 `X`로 정규화합니다.
- 잘못된 행렬·라벨·크기는 전체 프로그램을 중단하지 않고 케이스별 FAIL 사유로 남깁니다.
- 파일 자체가 없거나 JSON 루트가 손상된 경우에는 안내 메시지와 함께 종료 코드 1을 반환합니다.

## 보너스 과제

### 보너스 1: 2차원과 1차원 비교

같은 생성 패턴과 같은 필터, 같은 10회 반복 횟수를 사용해 `mac_2d()`와 `mac_1d()`를 비교합니다. 두 방식의 점수는 같아야 하며, 실제 시간은 실행 환경에 따라 달라집니다.

### 보너스 2: 패턴 생성기

`generate_cross(N)`과 `generate_x(N)`은 3 이상의 홀수 N을 받아 N×N 패턴을 생성합니다. 짝수·0·음수 크기는 `ValueError`로 거부합니다. 생성된 패턴은 벤치마크와 1차원 비교에서 재사용됩니다.

## 결과 리포트

2026-11-07에 원본 `data.json`으로 실행한 결과는 총 6개, PASS 3개, FAIL 3개였습니다. `size_5_2`, `size_13_1`, `size_25_2`는 각각 Cross 또는 X 점수가 분명히 높아 PASS가 되었습니다.

`size_5_1`, `size_13_2`, `size_25_1`은 원본 expected 라벨이 있지만 두 필터 점수가 EPSILON보다 작은 차이를 보여 `UNDECIDED`가 되었습니다. 이 케이스를 억지로 PASS로 만들기 위해 `data.json`이나 정답을 바꾸지 않았습니다. 오히려 부동소수점·가중치 데이터·동점 정책이 결합된 실패 원인을 케이스별로 출력하도록 했습니다.

한 번의 실행에서 측정된 예시는 다음과 같습니다. 시간은 CPU, 운영체제, 현재 부하에 따라 달라지므로 숫자 자체보다 10회 반복·ms 단위·N² 연산 수를 비교해야 합니다.

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|---:|---:|---:|
| 3×3 | 0.0026 | 9 |
| 5×5 | 0.0042 | 25 |
| 13×13 | 0.0166 | 169 |
| 25×25 | 0.0552 | 625 |

같은 실행에서 보너스 1은 3×3 Cross와 X의 MAC 점수가 1.000000으로 일치했습니다. 2차원 평균은 0.0022ms, 1차원 평균은 0.0018ms였지만, 이 차이는 작은 입력에서 측정 오차의 영향을 크게 받으므로 특정 구현이 항상 빠르다고 단정하지 않습니다.

## 실패 원인 분석

1. JSON 키가 `size_N_번호` 규칙을 따르지 않으면 N과 필터를 선택할 수 없어 해당 케이스를 FAIL 처리합니다.
2. N을 추출했지만 `filters.size_N`이 없으면 데이터/스키마 문제로 기록합니다.
3. 패턴과 필터의 행 수 또는 열 수가 다르면 MAC을 실행하지 않고 크기 오류를 기록합니다.
4. 행렬에 숫자가 아닌 값, NaN, 무한대가 있으면 수치 입력 문제로 분류합니다.
5. `+`, `cross`, `x` 이외의 라벨은 표준 라벨로 정규화할 수 없어 FAIL 처리합니다.
6. Cross 점수와 X 점수의 차이가 `1e-9` 미만이면 의도적으로 `UNDECIDED`를 반환합니다.
7. 모드 2는 `UNDECIDED`와 expected의 Cross/X를 같은 라벨로 보지 않으므로 FAIL로 집계합니다.
8. 정상 케이스에서 PASS가 되려면 정규화된 predicted 라벨과 expected 라벨이 정확히 같아야 합니다.
9. 파일 전체가 JSON으로 읽히지 않는 경우는 케이스 오류가 아니라 실행 설정 오류이므로 종료 코드 1을 반환합니다.
10. 케이스 단위 오류는 다음 케이스의 분석을 막지 않도록 `AnalysisReport.failures`에 누적합니다.
11. 원본 데이터의 라벨이나 점수를 수정하면 분석 결과가 좋아 보일 수 있지만, 그것은 데이터 분석이 아니라 데이터 변경이므로 하지 않았습니다.

## 시간 복잡도 분석

1. N×N 행렬의 각 위치를 한 번 방문하므로 MAC 한 번의 곱셈·누적 횟수는 N²입니다.
2. 따라서 MAC 시간 복잡도는 입력 크기 N에 대해 O(N²)입니다.
3. 3×3은 9회, 5×5는 25회, 13×13은 169회, 25×25는 625회입니다.
4. 25×25는 3×3보다 위치 연산 수가 약 69.4배 많습니다.
5. 성능 표의 평균 시간도 대체로 N²가 커질수록 증가해야 하지만, 작은 시간은 OS 스케줄링과 타이머 해상도의 영향을 받습니다.
6. `time.perf_counter()`는 파일 읽기와 콘솔 출력을 제외하고 MAC 호출 반복 구간만 측정합니다.
7. 각 크기를 10회 측정한 뒤 평균을 내므로 한 번의 우연한 지연이 결과에 미치는 영향을 줄입니다.
8. 1차원 방식도 N²개 원소를 모두 방문하므로 이론적인 시간 복잡도는 여전히 O(N²)입니다.
9. 1차원 배열은 인덱스 계산과 메모리 접근을 단순화할 수 있지만, Python에서는 리스트·반복문 오버헤드가 결과에 영향을 줍니다.
10. 실제 NPU는 이 MAC들을 병렬로 처리해 처리량을 높이지만, 이 과제의 시뮬레이터는 원리를 관찰하기 위해 순차 반복문을 사용합니다.
11. 데이터가 더 커지면 단순한 평균 시간만으로 하드웨어 성능을 판단하지 말고 반복 횟수·메모리 접근·병렬성도 함께 측정해야 합니다.
