# Mini NPU Simulator 설계 문서

## 의도

3×3부터 25×25까지의 숫자 패턴과 필터를 직접 곱하고 누적하는 MAC(Multiply-Accumulate) 과정을 콘솔에서 관찰하는 학습용 Python 애플리케이션을 만든다. 원본 `data.json`의 라벨과 배열을 변경하지 않고, 프로그램 안에서 `Cross`와 `X`로 정규화해 판정 결과와 예상값을 비교한다.

## 목표

- 외부 라이브러리 없이 이중 반복문으로 MAC 점수를 계산한다.
- 3×3 필터 A/B와 패턴을 한 줄씩 입력받는 모드 1을 제공한다.
- `data.json`의 `size_5`, `size_13`, `size_25` 필터와 패턴을 검증·분석하는 모드 2를 제공한다.
- 배열 크기·숫자·필터 존재 여부 오류를 케이스 단위 FAIL로 처리한다.
- `EPSILON = 1e-9` 기준으로 동점은 `UNDECIDED`로 판정한다.
- 크기별 최소 10회 MAC 평균 시간과 N² 연산 횟수를 출력한다.
- 보너스 1: 2차원 배열과 1차원 배열 MAC 성능을 같은 입력·반복 횟수로 비교한다.
- 보너스 2: 임의의 홀수 N에 대한 Cross/X 패턴을 생성하고 모드 1·성능 측정에 재사용한다.
- README에 결과 리포트, 실패 원인 분류, 시간 복잡도 O(N²), 보너스 비교 결과를 기록한다.

## 비목표

- NumPy, pandas 등 외부 패키지 사용
- CNN 전체 구현이나 실제 NPU 하드웨어 가속
- 원본 `data.json`의 정답·필터 값 수정
- 짝수 크기의 자동 Cross/X 생성

## 제약 및 입력 정책

- Python 3.8 이상, 표준 라이브러리만 사용한다.
- 모드 1은 정확히 3행, 각 행 3개의 유한한 숫자를 요구한다.
- JSON 배열은 정사각형이고 필터와 패턴의 크기가 같아야 한다.
- 패턴 키는 `size_N_번호`에서 정규식으로 N을 추출한다.
- `+`, `cross`는 `Cross`, `x`는 `X`로 정규화한다. 알 수 없는 라벨은 해당 케이스 FAIL 사유로 남긴다.
- `abs(score_a - score_b) < EPSILON`이면 `UNDECIDED`, 아니면 높은 점수의 필터 라벨로 판정한다.
- 모드 1의 두 필터는 각각 `A`, `B`로 표시하고 `A/B/UNDECIDED`를 출력한다. 모드 2는 필터 라벨을 `Cross/X`로 표시한다.
- 데이터 파일 자체가 없거나 최상위 JSON 구조를 읽을 수 없으면 오류를 출력하고 종료 코드 1을 반환한다. 파일을 읽은 뒤 발생하는 패턴·필터 오류는 해당 케이스만 FAIL로 처리한다.
- `patterns`가 비어 있으면 총 테스트 0건으로 요약하고 성능 표는 독립적으로 출력한다. 키 형식이 틀린 패턴도 총 테스트에 포함해 FAIL로 기록한다.
- extra JSON 필드는 허용하고, 필요한 `cross`·`x` 필터가 없거나 중복/알 수 없는 라벨이면 FAIL 사유를 기록한다.
- 벤치마크는 데이터 케이스에 의존하지 않고 생성된 Cross/X 행렬을 사용하므로 JSON 오류와 무관하게 실행된다. 3×3은 모드 1 결과 측정과 성능 표의 같은 10회 기준을 사용한다.

## 접근 방법

1. **단일 `main.py`**: 구현은 빠르지만 MAC, JSON 검증, 벤치마크, 보너스가 한 파일에 섞여 테스트와 설명이 어려워진다.
2. **기능 모듈 분리(선택)**: `main.py`는 메뉴·출력, `npu.py`는 계산·검증·분석·벤치마크를 담당한다. 표준 라이브러리만 사용하면서 테스트가 쉽고, 기본과 보너스의 동일 입력 비교를 보장하기 좋다.
3. **클래스 중심 설계**: `Simulator`, `Benchmark`, `JsonAnalyzer`를 여러 클래스로 나누면 확장성은 있지만 이 과제 규모에는 보일러플레이트가 늘어난다.

선택한 방식은 2번이다. 계산 규칙을 함수로 작게 나누고, CLI는 그 결과를 표시하는 역할만 맡긴다.

## 구성

- `main.py`: 모드 선택, 사용자 입력, 결과·성능·요약 출력, 종료 코드
- `npu.py`: `mac_2d`, `mac_1d`, `normalize_label`, `classify_scores`, 행렬 검증, JSON 분석, 벤치마크, Cross/X 생성
- `tests/test_npu.py`: MAC·동점·라벨 정규화·입력/JSON 오류·보너스 생성/성능 비교 테스트
- `data.json`: 과제에서 제공한 원본을 복사해 사용하며 내용은 변경하지 않음
- `README.md`: 실행 방법, 구현 요약, 결과 리포트, 복잡도 및 보너스 분석

## 실행 흐름

```text
main.py
 ├─ 1 → 3×3 행렬 입력 → mac_2d → 판정 → 3×3 성능
 └─ 2 → data.json 로드/검증 → 케이스별 MAC·PASS/FAIL
       → 3/5/13/25 성능 → 2D/1D 비교 → 전체 요약
```

JSON 분석은 한 케이스에서 오류가 발생해도 예외를 전체 실행으로 전파하지 않는다. 오류 케이스를 `FAIL` 목록에 기록하고 다음 패턴으로 진행한다.

## 성능 측정

`time.perf_counter()`로 MAC 함수 호출 구간만 측정한다. 각 크기에서 최소 10회 반복하고 평균을 ms로 표시한다. 연산 횟수는 한 번의 MAC이 수행하는 위치별 곱셈 수인 N²로 표시한다. 보너스 1은 같은 행렬과 같은 반복 횟수를 `mac_2d`와 `mac_1d`에 전달해 평균 시간을 비교한다.

실행할 때마다 실제 시간은 컴퓨터 상태에 따라 달라질 수 있으므로 숫자 자체가 아니라 측정 방법, 반복 횟수 10회, 단위 ms, N² 열을 재현성 기준으로 삼는다.

## 검증 기준

- 예시 Cross/X 3×3 입력에서 패턴에 맞는 점수가 더 높게 나온다.
- `data.json`의 모든 정상 케이스는 라벨 정규화 후 expected와 비교된다.
- 동점 케이스는 `UNDECIDED`이며, expected가 Cross/X이면 FAIL로 집계될 수 있다.
- 잘못된 행·열, 숫자, 라벨, 크기, 필터는 프로그램 중단 없이 케이스 FAIL로 표시된다.
- 테스트 전체가 통과하고 `python main.py`의 두 모드가 실행된다.
- `python -m unittest -v`로 테스트를 재실행할 수 있고, 정상 모드 실행은 종료 코드 0, 파일 자체 오류는 종료 코드 1이다.
- `UNDECIDED`는 expected가 `Cross` 또는 `X`일 때 PASS가 아니라 FAIL이다.
